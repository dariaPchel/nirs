# FRAUDI — помощник по выявлению признаков онлайн-мошенничества

## О проекте
FRAUDI — интеллектуальный помощник, который помогает пользователю разобраться в подозрительной ситуации: звонке, сообщении, ссылке или просьбе перевести деньги либо сообщить код подтверждения. Пользователь описывает произошедшее своими словами; помощник ищет релевантные сведения в базе из 30 документов с помощью **BM25** (реализован с нуля) и формирует объяснимый ответ с опорой на источники с помощью LLM (Groq).

Проект разрабатывается в рамках НИРС «Разработка RAG-приложения с помощью LLM» в МГТУ им. Н. Э. Баумана.

## Быстрый запуск

Нужны Python 3.10+ (проверено на 3.14), Git и API-ключ Groq ([console.groq.com/keys](https://console.groq.com/keys)).

1. Склонировать репозиторий и установить зависимости:

   ```bash
   git clone https://github.com/dariaPchel/nirs.git
   cd nirs
   pip install flask flask-cors groq python-dotenv
   ```

2. Создать файл `.env` в корне проекта:

   ```env
   GROQ_API_KEY=gsk_ваш_ключ
   GROQ_MODEL=openai/gpt-oss-20b
   ```
   Чтобы получить свой БЕСПЛАТНЫЙ API-ключ для проверки работы проекта:
   1) Включите VPN
   2) Перейдите, пожалуйста, по ссылке: https://console.groq.com/keys
   3) Создайте новый ключ и вставьте его в .env файл в GROQ_API_KEY

   Ограничения есть только в запросах в минуту, если превысит, нужно будет немного подождать

4. Запустить бэкенд (первый терминал):

   ```bash
   cd app/backend
   python main.py
   ```

   Ожидаемый вывод: `🚀 Сервер запущен: http://127.0.0.1:5000`

5. Запустить фронтенд (второй терминал):

   ```bash
   cd app/frontend
   python -m http.server 8000 --bind 127.0.0.1
   ```

   `--bind 127.0.0.1` нужен при включённом VPN, иначе локальные запросы могут уйти в туннель.

6. Открыть в браузере:
   - лендинг: <http://127.0.0.1:8000/landing.html>
   - чат: <http://127.0.0.1:8000/chat.html>

   Открывайте именно `127.0.0.1`, а не `localhost`: адрес бэкенда в `chat.html` прописан как `http://127.0.0.1:5000`.

## Основной сценарий
1. Пользователь описывает подозрительную ситуацию.
2. Запрос уходит на `POST /ask`, где по описанию выполняется поиск по корпусу документов с помощью BM25 (top-3).
3. Найденные документы вместе с вопросом передаются LLM; каждый документ помечен идентификатором (`D01`–`D30`).
4. LLM формирует ответ только на основе найденного контекста. Если подходящих сведений в корпусе нет, она сообщает об этом, а не выдумывает ответ.
5. Пользователь получает объяснение признаков, рекомендуемые действия и список источников.

Пример: пользователь сообщает, что ему позвонили от имени службы безопасности банка и попросили продиктовать код из СМС для отмены кредита. Помощник объясняет, почему это тревожный признак, и рекомендует прекратить разговор и связаться с банком через официальный канал.

```text
Вопрос → Flask /ask → BM25 (top-3) → контекст + вопрос → Groq LLM → { answer, sources } → чат
```

## Как работает поиск
Документы токенизируются (нижний регистр, без пунктуации), индекс `слово → документ → частота` строится один раз при запуске сервера. Балл документа:

```text
BM25(q, d) = Σ IDF(t) · tf·(k₁ + 1) / (tf + k₁·(1 − b + b·L/avgdl))
IDF(t)     = ln(1 + (N − df + 0.5) / (df + 0.5))
```

## API

### `POST /ask`

Запрос:

```json
{ "question": "Мне позвонили из банка и попросили код из СМС" }
```

Ответ `200 OK`:

```json
{
  "answer": "Это типичная схема мошенничества. Настоящие сотрудники банка никогда не запрашивают коды из СМС...",
  "sources": [
    { "id": "D01", "schema": "Просят перезвонить «госслужащие»" },
    { "id": "D06", "schema": "Мошенники представляются сотрудниками мобильного оператора" }
  ]
}
```

Ошибка `400` при пустом вопросе: `{ "error": "Вопрос не задан" }`.

## Benchmark
Одинаковая проверка для каждой версии поиска: фиксированный корпус, фиксированные вопросы, одна глубина `k = 3`.

- `benchmark/request.md` — описание вопросов, ожидаемого поведения и источников.
- `app/backend/benchmark/benchmark.json` — набор для автоматического прогона.
- `app/backend/benchmark/benchmark.py` — скрипт прогона и подсчёта метрик.
- `app/backend/benchmark/results/` — результаты прогонов.

| Часть | Количество | Описание |
|---|---|---|
| Документы | 30 | ID `D01`–`D30` |
| Обычные вопросы | 10 | Ответ есть в корпусе, указаны релевантные документы |
| Вопросы-ловушки | 5 | Ответа в корпусе нет, ожидается отказ или уточнение |

Как повторить проверку:

1. Убедиться, что в `.env` указан ключ Groq.
2. Запустить скрипт:

   ```bash
   cd app/backend/benchmark
   python benchmark.py
   ```

3. Открыть результаты в `app/backend/benchmark/results/` и сравнить ожидание с результатом

## Ограничения и границы проекта
1. **Лексический поиск:** BM25 ищет совпадения слов. Если пользователь описал ситуацию совершенно другими словами, документ может не попасть в Top-3.
2. **Фиксированный корпус:** Ответы формируются строго на основе 30 документов базы знаний. Система не использует общие знания LLM для выдумывания фактов.
3. **Отказ от ответа:** Если в Top-3 нет релевантной информации или вопрос является "ловушкой" (не относится к мошенничеству), система корректно сообщает об отсутствии данных.
4. **Не является юридической консультацией:** Приложение не устанавливает личность звонившего, не доказывает факт преступления и не заменяет обращение в полицию или банк.
5. **Без авторизации:** Прототип не требует входа в систему и не имеет доступа к реальным банковским счетам или базам данных операторов связи.

## Решение типовых проблем

| Проблема | Причина | Решение |
|---|---|---|
| `groq.PermissionDeniedError: 403` | Неверный или отозванный ключ | Создайте новый ключ и обновите `.env` |
| `groq.RateLimitError: 429` | Исчерпан дневной лимит модели | Смените `GROQ_MODEL` на `llama-3.1-8b-instant` или `llama-3.3-70b-versatile` |
| Ошибка соединения в чате | Бэкенд не запущен или VPN перехватывает локальный трафик | Проверьте, что `main.py` работает; используйте `--bind 127.0.0.1` и адрес `127.0.0.1` |
| `WinError 10013` | Порт 5000 или 8000 занят | Возьмите другой порт или завершите процесс через `taskkill` |
